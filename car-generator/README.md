# RayCity Car Generator

เครื่องมือสร้างโมเดลรถ 3 มิติแบบ procedural สำหรับเกม RayCity: ปรับรูปทรงด้วยสไลเดอร์ แล้วส่งออกเป็นไฟล์ `.glb` / `.obj` ไปใช้ใน Unity, Unreal, Godot หรือ Blender

## วิธีเปิดใช้งาน

**ง่ายที่สุด:** ดับเบิลคลิกไฟล์ `RayCity-Car-Generator.html` ได้เลย ไฟล์เดียวจบ ไม่ต้องลงโปรแกรม ไม่ต้องต่อเน็ต
(ก๊อปไฟล์นี้ไปไว้ที่ไหนก็เปิดได้)

### สำหรับคนแก้โค้ด

หลังแก้ไฟล์ใน `js/` หรือ `style.css` ให้สร้างไฟล์ HTML ไฟล์เดียวใหม่ด้วย:

```bash
cd car-generator
npm install
npm run build
```

ระหว่างพัฒนาจะเปิด `index.html` ผ่าน web server ก็ได้:

**Windows:** ดับเบิลคลิก `start.bat` ในโฟลเดอร์ `car-generator` (ต้องมี Python) โปรแกรมจะเปิดในเบราว์เซอร์ให้เอง

**วิธีพิมพ์คำสั่งเอง:** ต้อง `cd` เข้าโฟลเดอร์ `car-generator` ก่อน ไม่อย่างนั้นจะเห็นแค่รายชื่อไฟล์ (Directory listing)

```bash
cd path/to/raycityPG/car-generator
python -m http.server 8000 --bind 127.0.0.1
# แล้วเปิด http://localhost:8000
```

(เปิดไฟล์ `index.html` ตรงๆ ด้วยการดับเบิลคลิกไม่ได้ เพราะเบราว์เซอร์ไม่โหลด ES modules จาก `file://`)

หรือ `npx serve car-generator` ก็ได้ (ต้องต่ออินเทอร์เน็ต เพราะโหลด three.js จาก CDN)

## ความสามารถ

- **แบบรถสำเร็จรูป 11 แบบ**: ซูเปอร์คาร์ V12, ไฮเปอร์คาร์, GT สปอร์ต, SUV คูเป้หรู, ซีดาน, สปอร์ต, แฮทช์แบ็ก, SUV, กระบะ, มัสเซิล, รถเล็ก
- **สุ่มรถ** พร้อม Seed (ใส่เลข seed เดิมจะได้รถคันเดิมทุกครั้ง)
- รายละเอียดสมจริง: ไฟหน้าโปรเจกเตอร์ + DRL, กระจังแบบซี่/ตาข่าย/ไตคู่, ไฟตัดหมอก, ช่องลมล่าง, ร่องประตู + มือจับ,
  ห้องโดยสาร (เบาะ, คอนโซล, พวงมาลัย ซ้าย/ขวา) มองผ่านกระจกใสได้, สีเคลือบเงา (clearcoat), แม็กเว้า + น็อตล้อ
- ทรงซูเปอร์คาร์: หน้าแหลมแบบลิ่ม, สะโพกหลังบาน, ห้องโดยสารทรงหยดน้ำ, ช่องรับลมหน้า/ข้าง, ครีบฝาครอบเครื่อง, ไฟหน้าเฉียงคม, ไฟท้ายตัว Y
- ปรับได้ทุกส่วน: ความยาว/กว้าง/สูง, ฝากระโปรง, ห้องโดยสาร, ตำแหน่งกระจก, ล้อ, ลายแม็ก, ไฟหน้า/ท้าย,
  สปอยเลอร์, ลิ้นหน้า, ดิฟฟิวเซอร์, สเกิร์ต, สกู๊ป, แร็คหลังคา, แถบคาด, ไฟใต้ท้อง (neon) และสี/วัสดุ
- ระดับความละเอียด Low / Medium / High + โหมด Flat shading สไตล์ low-poly
- **ทดลองขับ** ในหน้าเว็บ (W A S D / ลูกศร, Space เบรก, R รีเซ็ต) เพื่อเช็คว่าล้อหมุนและเลี้ยวถูกต้อง
- ส่งออก `.glb` (แนะนำ), `.obj`, ภาพ `.png` และบันทึก/โหลดค่าเป็น `.json`
- ค่าล่าสุดถูกจำไว้ในเบราว์เซอร์อัตโนมัติ

## โครงสร้างโมเดลที่ส่งออก

- หน่วยเป็น **เมตร**, แกน **Y ขึ้น**, หน้ารถหันไปทาง **+Z**, จุด origin อยู่ที่พื้นกึ่งกลางตัวรถ
- ฝั่งซ้ายของรถคือ +X, ฝั่งขวาคือ −X

```
<ชื่อรถ>
├── Body          (วัสดุ: Paint, Stripe, Trim)
├── Cabin         (วัสดุ: Paint, Stripe, Trim, Glass)
├── Details
│   ├── Lights    (Headlight_L/R, Taillight_*)
│   └── Grille, Mirror_L/R, Spoiler_*, Exhaust, ...
├── Wheel_FL      ← pivot อยู่กลางล้อ (ใช้หมุนเลี้ยว)
│   ├── Wheel_FL_Spin   ← หมุนแกน X เพื่อให้ล้อหมุน
│   │   └── Tire, Rim, RimInner, BrakeDisc
│   └── Caliper   (ไม่หมุนตามล้อ)
├── Wheel_FR
├── Wheel_RL
└── Wheel_RR
```

ชื่อวัสดุ (Paint, Glass, Tire, Rim, Headlight, Taillight ฯลฯ) คงที่ทุกคัน จึงเปลี่ยนสีรถในเกมได้ด้วยการแก้วัสดุ `Paint` อย่างเดียว

## นำเข้าเกมเอนจิน

- **Unity**: ติดตั้ง [glTFast](https://docs.unity3d.com/Packages/com.unity.cloud.gltfast@latest) (หรือ UnityGLTF) แล้วลากไฟล์ `.glb` เข้า Assets
  ผูก `WheelCollider` กับ `Wheel_XX` และให้สคริปต์หมุน `Wheel_XX_Spin` ตามความเร็ว
- **Unreal**: Import `.glb` ได้โดยตรง (UE5) หรือแปลงเป็น `.fbx` ผ่าน Blender สำหรับ Chaos Vehicle (ต้องตั้ง skeleton ล้อ)
- **Godot 4**: ลาก `.glb` เข้าโปรเจกต์ได้เลย ใช้ `VehicleBody3D` + `VehicleWheel3D` ที่ตำแหน่ง `Wheel_XX`
- **Blender**: File → Import → glTF 2.0 แล้ว export เป็น `.fbx` ได้ถ้าเอนจินต้องการ

## ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `RayCity-Car-Generator.html` | **ไฟล์สำหรับใช้งาน** (สร้างจาก `npm run build` รวมทุกอย่างไว้ในไฟล์เดียว) |
| `index.html`, `style.css` | หน้าจอโปรแกรม (ต้นฉบับ) |
| `build.mjs` | สคริปต์รวมไฟล์เป็น HTML ไฟล์เดียว |
| `js/carBuilder.js` | สร้าง geometry ของรถจากพารามิเตอร์ (ตัวถัง loft, ห้องโดยสาร, ล้อ, ชุดแต่ง) |
| `js/params.js` | รายการพารามิเตอร์ (สร้าง UI อัตโนมัติ), ค่าเริ่มต้น, presets และระบบสุ่ม |
| `js/main.js` | ฉาก 3D, UI, การส่งออก และโหมดทดลองขับ |

อยากเพิ่ม preset ใหม่: เพิ่ม entry ใน `PRESETS` ใน `js/params.js` (ใส่เฉพาะค่าที่ต่างจาก `DEFAULTS`)
อยากเพิ่มสไลเดอร์: เพิ่ม item ใน `SCHEMA` แล้วใช้ค่า `p.<key>` ใน `carBuilder.js`

## ไฟล์รถ RayCity (.0m)

ปุ่ม **👁 ดูแบบในเกม** (มุมบนซ้ายของจอ 3D) วาดผิวด้านเดียวเหมือนเกม ใช้หาช่องโหว่ก่อนเอาเข้าเกม

รถที่สร้างไว้ใน `cars/` (เช่น `rc_italia`) ถูกฝังไว้ในไฟล์ HTML ตอน `npm run build` กดปุ่ม 🏎 ด้านบนสุดเพื่อดูได้ทันที
(ฝังทั้งโฟลเดอร์แบบบีบอัด ทุก LOD ทุกไฟล์)

ปุ่ม **⬇ ดาวน์โหลดรถคันนี้ทั้งโฟลเดอร์ (.zip)** ดาวน์โหลดทุกไฟล์ของรถที่เปิดอยู่ตอนนี้ — ทั้งรถ 🏎 ที่ฝังไว้
และโฟลเดอร์ / ไฟล์ .0m ที่เปิดหรือลากมาวาง — แตก zip แล้วได้โฟลเดอร์ `<ชื่อรถ>/` โครงสร้างเดียวกับต้นฉบับ
ถ้าแก้ค่าในส่วนสเปครถ ไฟล์ `<ชื่อรถ>.xml` ใน zip จะเป็นค่าที่แก้แล้ว

ส่วน **RayCity (.0m)** ในแถบซ้าย:

- **📂 เปิดทั้งโฟลเดอร์รถ:** เลือกโฟลเดอร์รถ (เช่น `car/escarabajo`) หรือลากโฟลเดอร์มาวางบนจอ 3D
  โปรแกรมจะอ่าน `list.xml` ของแต่ละโฟลเดอร์ย่อย (`hood`, `frontbumper`, `roof` ...) แล้วประกอบตัวถัง + ชิ้นส่วนแบบ `default` ให้
  เลือกเปลี่ยนแบบของแต่ละชิ้น (เช่น `rbrc_001`, `h11000`) และระดับรายละเอียด LOD 0/1/2 ได้
  ลายของชิ้นส่วนมาจากค่า `tex` ใน `list.xml` ถ้า `tex` ว่างหรือหาไฟล์ไม่เจอ จะใช้มาสก์สีของตัวถังแทน
  UV ของทุกชิ้นชี้เข้าไปในลายตัวถัง 512×512 เดียวกัน (สีรถมาจากมาสก์นี้) ส่วนลายของชิ้น (โคมไฟ ตะแกรง)
  เป็นภาพสีจริง และช่อง alpha คือมาสก์ความเงา ยังไม่รู้ว่าเกมแปะลงตรงไหน หน้าเว็บจึงแสดงเป็นสีรถไปก่อน
  กระจกและไฟแสดงตามชนิด submesh (ธงในไฟล์ .0m)
  มาสก์สี (`*_base.png`) ถูกระบายใหม่: แดง = สีตัวถัง (รวมกระจก), เขียว/น้ำเงิน = สีตัวถังเหมือนกัน หรือ "สีที่สอง" ถ้าเปิดทูโทน
  (ใน escarabajo บริเวณน้ำเงินคือฝากระโปรง)
- **เปิดไฟล์ .0m:** เลือกไฟล์ `body_*.0m` ได้หลายไฟล์พร้อมกัน แต่ละชิ้นส่วน (submesh) จะแสดงเป็นสีต่างกัน
  ถ้าเลือกไฟล์ `.png` ลายรถมาด้วย จะแสดงพร้อมลาย จากนั้นกด "ส่งออก .GLB/.OBJ" เพื่อเอาไปแก้ใน Blender/3ds Max ได้
- **ส่งออก .0m (ทดลอง):** แปลงรถจากตัวสร้างรถ (เฉพาะตัวถัง ไม่รวมล้อ) เป็นไฟล์ `.0m`
  ต้องเปิดไฟล์ `.0m` ของรถในเกมก่อน 1 ไฟล์ เพื่อใช้เป็น "แม่แบบ" (ส่วนหัวไฟล์ที่ยังแกะไม่ออกจะถูกคัดลอกมาจากไฟล์นี้)
  ไฟล์ที่ได้จะชื่อเดียวกับแม่แบบ แนะนำให้ตั้งความละเอียดเป็น "ต่ำ" ก่อนส่งออก

> ⚠️ ยังไม่ได้ทดสอบในเกมจริง ให้ก๊อปโฟลเดอร์รถเดิมไว้ก่อนแล้วค่อยแทนที่ไฟล์ `.0m`

### โครงสร้างไฟล์ .0m ที่แกะได้ (little endian)

| ส่วน | รายละเอียด |
|---|---|
| หัวไฟล์ | magic `AA 47 47 03` ตามด้วยข้อมูลฉาก/ตำแหน่ง (ยังไม่ได้แกะ) |
| ธงของ submesh | 3 ไบต์ก่อนแต่ละ record: ไบต์แรก = ชนิด 0 สี/ลาย, 1 กระจก, 2 เลนส์ไฟหน้า, 3 ไฟท้าย/เบรก, 4 ไฟเลี้ยว/ถอย · ไบต์ 2–3 ใช้กับชิ้นที่ขยับได้ (ยังไม่ได้แกะ) |
| ตารางชิ้นส่วน | `FF`, u8 จำนวนชิ้น, 4 ไบต์ที่ยังไม่รู้ความหมาย แล้วตามด้วย record ห่างกัน 28 ไบต์ (ชิ้นสุดท้าย 25 ไบต์): +1 u16 จำนวนจุด, +3 u16 จำนวน index, +5/+9/+17 `[01, pad, u16 จุดเริ่ม]`, +21 `[01, pad, u16 index เริ่ม]` |
| รูปทรง | bbox (6×f32) · u16 n + ตำแหน่ง n×float3 · u16 n + normal n×float3 · u16 0 · u16 n + UV n×float2 · u16 m + index m×u16 (นับแยกในแต่ละชิ้น) |

แกนของ RayCity: Z ชี้ขึ้น, หน้ารถไปทาง −Y, ด้านซ้ายคือ +X · ทิศหน้าสามเหลี่ยมเหมือน three.js หลังแปลง `(x, y, z) → (x, z, −y)`
ตัวอ่านใน `js/om.js` อ่านแล้วเขียนกลับได้ไฟล์เหมือนต้นฉบับทุกไบต์ (ทดสอบกับไฟล์ `.0m` ทั้ง 171 ไฟล์ใน `samples/escarabajo.rar`)

### ไฟล์สเปครถ (`<รถ>.xml`)

ส่วน **สเปครถ (.xml)** แก้ค่าที่ใช้บ่อยได้: น้ำหนัก (`BD_Mass`), จุดศูนย์ถ่วง (`BD_Offset`), แรงบิด/รอบเครื่อง (`EG_*`),
อัตราทดเกียร์ (`MS_Ratio`), รัศมีล้อขับ (`MS_TractionRadius`), การเกาะถนน/เบรก (`TI_Mu`, `BK_Mu`), มุมเลี้ยว (`ST_MaxAngle`),
ช่วงล่าง (`SU_Height`), บูสต์ (`BT_*`), โลโก้ และช่องเก็บของ
- เปิดโฟลเดอร์รถแล้ว ถ้ามี `<ชื่อรถ>.xml` อยู่ในโฟลเดอร์ จะโหลดให้อัตโนมัติ หรือกด "เปิด .xml" เอง
- "ค่าแนะนำจากรถ" ประมาณน้ำหนัก รัศมีล้อ และความสูงช่วงล่างจากรถที่สร้าง
- ส่งออกเป็น UTF-16 + CRLF เหมือนไฟล์ของเกม แท็กอื่นและคอมเมนต์คงไว้ตามต้นแบบ (ต้นแบบในตัวคือ `samples/escarabajo/escarabajo.xml`)

### โครงสร้างโฟลเดอร์รถ

```
escarabajo/
├── body_0.0m, body_1.0m, body_2.0m     ตัวถัง LOD 0–2 (2 = ละเอียดสุด)
├── escarabajo_base.png / _s.dds          มาสก์สีตัวถัง (_s = ขนาดเล็ก)
├── mesh.xml                               กล่องชน (collision) แบบหยาบ
├── <รถ>.xml                               สเปครถ (ฟิสิกส์ เครื่องยนต์ บูสต์ สี กล้อง)
├── <ชิ้นส่วน>/list.xml                    รายชื่อแบบ: <part name mesh tex/>
├── <ชิ้นส่วน>/<mesh>_0..2.0m              โมเดลแต่ละแบบ
├── <ชิ้นส่วน>/<tex>.png                   ลายของชิ้น
├── dooropen/default.xml                   เวลาเปิด/ปิดประตู (doorani)
└── icon/<รถ>_<ชิ้นส่วน>_<แบบ>.png         ไอคอนในร้านแต่งรถ
```
มีตัวอ่านภาษา Python สำหรับแกะไฟล์อยู่ใน `tools/`

## สร้างรถ RayCity จากโมเดลรถจริง (`tools/build-car.mjs`)

แปลงโมเดล `.glb` รถสมจริง (เช่นจาก Sketchfab ที่อนุญาตให้ใช้) เป็นโฟลเดอร์รถ RayCity โครงเดียวกับรถในเกมทุกอย่าง

```bash
cd car-generator
npm install
node tools/build-car.mjs model.glb path/to/car/escarabajo out/rc_mycar --name rc_mycar [--keep-logos] [--raw] [--budget 0.5] [--max-verts 7000]
node tools/make-icons.mjs out/rc_mycar path/to/car/escarabajo      # ไอคอนร้านแต่ง 64×64 (ต้องมี Chromium)
node tools/fix-anim.mjs out/rc_mycar path/to/car/escarabajo        # แก้รถที่สร้างก่อนหน้านี้ (ดูด้านล่าง)
```

สิ่งที่ตัวแปลงทำ:
- แบ่งโมเดลตามตำแหน่ง/วัสดุเป็นชิ้น: `body`, `hood`, `roof`, `frontbumper`, `rearbumper`, `headlight`, `rearlight`, `skirt`
  และสร้างสปอยเลอร์หลัง 5 แบบให้ช่อง `mainspoiler`
- ข้ามล้อ (เกมใช้ล้อกลาง) และโลโก้ยี่ห้อ (ชิ้นเล็กๆ ที่หน้า/ท้ายรถ)
- เก็บแผงด้านในเฉพาะที่ปิดช่องโหว่: ห้องโดยสาร (พื้น คอนโซล แผงประตู), บังโคลนในซุ้มล้อ, ใต้ท้อง
  ลดด้วย vertex clustering (ไม่เกิน 3 ซม.) และวาดสองด้าน ส่วนห้องเครื่อง/โครงในกันชนตัดทิ้ง (จะโผล่ทะลุผิว)
- ชิ้นที่หันทั้งเข้าและออก (ขอบโคม ลิ้น ครีบ) วาดสองด้าน ที่เหลือหันออกด้านเดียวเหมือนเกม
- ลบหน้าที่ซ้อนสองชั้น หันทุกหน้าออกนอกรถ (เกมวาดหน้าเดียว) แล้วลด poly เป็น LOD 0/1/2 ด้วย meshoptimizer
  โดยล็อกรอยต่อแผงไม่ให้ขาด และปรับลดอัตโนมัติจนไม่เกินขีดจำกัดของไฟล์ `.0m` (65,535)
- ทำลายแบบจานสี: ชิ้นที่เป็นสีรถใช้มาสก์ (แดง = สีรถ), ไฟใช้สีจริง พร้อมไฟล์ `_s.dds`
  ขนาดภาพเท่ารถแม่แบบ (base 512×512, color 128×64 ...) และ `_s.dds` เป็น DXT3 + mipmap เหมือนไฟล์ในเกม
  ทุกโฟลเดอร์ชิ้นส่วนมีเท็กซ์เจอร์ `<ชื่อรถ>_<ชิ้น>.png/_s.dds` และ `list.xml` อ้างชื่อตามแบบแม่แบบ
- เขียน `.0m` โดยใช้ไฟล์ของรถแม่แบบ (ช่อง/LOD เดียวกัน) เป็นส่วนหัว, `list.xml` ใช้ id/ชื่อแบบเดิมทั้งหมด
  (ทุกแบบชี้ไปที่ชิ้น `default` เพื่อให้ไอเท็มในร้านยังใช้ได้), `mesh.xml` (กล่องชนยืดตามขนาดรถ), `dooropen`, ไฟล์สเปค

ใช้ได้กับโมเดลทั่วไป: จัดกลุ่มวัสดุเองจากชื่อ (สีรถ/กระจก/ไฟหน้า/ไฟท้าย/ไฟเลี้ยว/โครเมียม/พลาสติก/ภายใน),
หาหน้ารถจากตำแหน่งล้อหน้า-หลัง (หมุนให้เอง) และปรับระยะทุกค่าตามขนาดรถ (ซูเปอร์คาร์เตี้ย ถึงกระบะ)
`--raw` โหมดตามต้นฉบับ: ไม่เพิ่ม/ไม่ลบอะไรนอกจากล้อ ใช้ normal และค่าสองด้านของต้นฉบับ ลด poly ให้เต็มความจุทุกไฟล์ (~20k ต่อไฟล์)
**ชิ้นที่ขยับได้ (ประตู ฝากระโปรง):** ในไฟล์ `.0m` แต่ละ submesh มี flags 3 ไบต์ `[ชนิด, กลุ่ม, ลำดับ]`
เช่น `[0,1,0]`/`[0,1,1]` = ประตูซ้าย/ขวา (door 0/1 ใน `dooropen`), `[0,1,2]` = ฝากระโปรง, `[1,1,0]` = กระจกประตู
escarabajo เก็บประตูไว้ในไฟล์ `roof` เกมหาชิ้นเหล่านี้ตอนเปิดประตูในโรงรถ ถ้าไม่มีจะเด้ง
ตัวแปลงจึงเรียง submesh ตามไฟล์แม่แบบทุกไฟล์ และใส่สามเหลี่ยมซ่อนขนาด 1 มม. ในตำแหน่งชิ้นที่ขยับได้ที่รถเราไม่มี
(`tools/fix-anim.mjs` ทำแบบเดียวกันกับโฟลเดอร์รถที่สร้างไว้แล้ว)

`--max-verts N` จำกัดจุดต่อไฟล์ `.0m` — รถในเกมจริงมีไม่ถึง 2,000 จุดต่อไฟล์ และรวมทั้งคันไม่ถึง 6,000
ถ้ารถเด้งออกจากเกมตอนเปิดในโรงรถ ให้ลดลง (กระบะ `rc_canyon` ใช้ `--raw --budget 0.5 --max-verts 7000` รวม LOD2 ≈ 44k จุด)
`--keep-logos` เก็บโลโก้/ตัวอักษรยี่ห้อไว้ (ไม่งั้นจะลบ ซึ่งอาจทิ้งรูไว้) · ป้ายทะเบียนลบเสมอ เพราะเกมใส่ป้ายเอง
